# Mnemo — public retrieval-quality benchmarks (Letta-parity layout)

> **What changed (2026-08-03):** this page shipped in April 2026 with the mnemo
> rows `_pending_`, waiting on an authenticated LLM-judged nightly run that never
> landed (the OpenAI/Anthropic/HF secrets in issue **#44** were never wired). The
> project has since pivoted the benchmark to a **credential-free retrieval-quality**
> harness — gold-document recall@k / MRR over a **real local semantic embedder** —
> which is what `docs/benchmarks/baseline.json` has recorded since 2026-06-29. The
> mnemo rows below are now **populated from a fresh run of that harness on this
> machine** (see hardware + reproduce command). They are **retrieval** numbers, not
> LLM-judged QA — do not compare them to the reference leaderboard rows, which score
> a generative model's answers (see the caveat under the reference table).

**Harness:** `mnemo-locomo-bench :: semantic_recall_bench` (Rust)
**Embedder:** Ollama `nomic-embed-text`, **768-dim**, local, cosine HNSW — never NoopEmbedding (the runner refuses to score without a real embedder)
**Metric:** gold-document **recall@k + MRR** (retrieval quality). No generative LLM and no LLM judge run in this harness.
**Dataset:** bundled `longmemeval_m` 45-record slice → corpus fully seeded; queries split into **eval = 23 (held-out, even indices)** / tune = 22 (odd). **5 in-process seeds**, means reported with the per-seed recall@5 spread.
**Run:** 2026-08-03 · Apple M4 (10-core), 16 GB · macOS 26.5.2 (arm64) · rustc 1.97.0 · Ollama 0.32.3

### Reproduce (no credentials, no API keys)

```bash
ollama pull nomic-embed-text
cargo run --release -p mnemo-locomo-bench --bin semantic_recall_bench
```

Writes `bench/locomo/results/semantic_recall_<date>.{md,json}` and prints the table below.

> **These are NOT comparable to the mnemo rows below.** The reference numbers are
> **end-to-end LLM-judged QA accuracy** — a generative model answers, and a judge
> grades the answer. The mnemo rows are **retrieval quality** — did the gold document
> land in the top-k — with no generative model in the loop. mnemo's `vector_only`
> recall@10 of 1.000 means "the gold doc was in the top 10 for every one of the 23
> held-out queries on this small slice," **not** that mnemo out-answers Hindsight.
> End-to-end LLM-judged QA accuracy for mnemo is deliberately left unmeasured here
> (it needs a generative LLM + judge key); see `baseline.json`
> `datasets.longmemeval_qa_accuracy` (empty on purpose).

## Mnemo numbers (retrieval quality — this run, 2026-08-03)

| Strategy | recall@5 | recall@10 | MRR | p50 ms | p95 ms | p99 ms |
|:--|--:|--:|--:|--:|--:|--:|
| `auto` | 0.809 | 0.957 | 0.604 | 42.1 | 50.2 | — |
| `vector_only` | 0.826 | 1.000 | 0.806 | 39.0 | 51.2 | — |
| `hybrid_rrf` | 0.826 | 0.957 | 0.766 | 42.1 | 48.3 | — |
| `graph_boosted` | — | — | — | — | — | — |

Row mapping to the harness modes (the harness's own labels are in
`semantic_recall_2026-08-03.json`):

- **`auto`** = the harness `rrf_hybrid` mode — mnemo's default `auto` strategy with
  equal RRF lane weights.
- **`vector_only`** = harness `vector_only` (`strategy = "semantic"`, USearch HNSW cosine).
- **`hybrid_rrf`** = harness `rrf_hybrid_tuned` — `auto` with the best swept weights
  from a held-out sweep (this run selected `[6,1,0,0]`, `k=30`).
- **`graph_boosted`** — **empty by design.** This retrieval harness has no distinct
  graph-boosted mode; the best swept hybrid config put **zero weight on the graph
  lane**, so there is no honest graph-boosted number to report from this run. The
  `mnemo-graph` crate exists, but a graph-boosted retrieval arm is not wired into
  `semantic_recall_bench`.
- **`p99`** — **empty by design.** Each seed contributes only 23 latency samples, so a
  per-seed p99 is just the max; there are not enough samples for a meaningful tail. p50
  and p95 are reported instead.

**Run-to-run spread (recall@5, min–max over 5 seeds):** `vector_only` [0.826, 0.826],
`hybrid_rrf` [0.826, 0.826], `auto` [0.783, 0.826]. Recall is stable across seeds on
this slice; latency (p50/p95) varies with machine and load.

### Honest reads, including the losses

- **The default `auto` fusion loses to pure vector on ranking quality.** `auto` MRR
  **0.604** vs `vector_only` **0.806** — on this slice mnemo's default equal-weight RRF
  actively *hurts* rank-1 precision (it drags in BM25 candidates). Tuning the weights
  (`hybrid_rrf`) recovers most of it (MRR 0.766) but still does not beat pure vector.
  `vector_only` is the one stable strong mode — which is exactly what the README
  headline says.
- **Lexical floor (not a page row, reported for honesty):** the harness `bm25_only`
  mode scores recall@5 **0.739**, recall@10 0.739, MRR **0.586** — it loses to
  `vector_only` on every metric, as expected for a semantic-recall task.
- Small slice (n=23 held-out): treat sub-0.05 gaps as ties and the numbers as
  directional, not leaderboard-grade.

## LoCoMo / LongMemEval LLM-judged QA (the leaderboard axis) — not run here

The Python `mnemo.benches.locomo_runner` harness (LongMemEval_S / LoCoMo-MC10, LLM
judge) produces the leaderboard-comparable recall@10 / QA-accuracy numbers, but needs
`OPENAI_API_KEY` + `ANTHROPIC_API_KEY` + gated `HF_TOKEN` (issue **#44**), none of which
are set. Those rows stay unmeasured rather than estimated. When the secrets are wired,
`.github/workflows/benchmarks-nightly.yml` runs it nightly and the gate in
`.github/scripts/check_bench_regression.py` fails on a >3pp recall@10 regression.
